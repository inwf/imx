# 性能说明

## 资源管理

一个用户的全部会话由一个单线程后台进程管理。后台进程使用 `epoll` 和 `signalfd` 等待事件；没有输入、输出或控制请求时，阻塞等待内核通知。

创建会话及最后一个客户端分离时，调用终端库的页面容量压缩和释放接口，释放闲置的预留页面。持续输出期间使用页面池；光标仍然持有样式或超链接引用的页面保持引用表。

| 项目 | 限制或处理方式 |
| --- | --- |
| 历史 | 10,000 行目标及 2 MiB 的历史容量，按完整终端页面修剪 |
| 当前屏幕和终端状态 | 另行占用内存 |
| 实时输入、输出队列 | 每个队列最多 256 KiB |
| 终端快照 | 按 16 KiB 分批发送，后续实时输出保持顺序 |
| 慢速连接 | 超过输出容量限制时断开，会话继续运行 |
| 终端尺寸 | 最多 512 列、256 行 |

## 测量环境

以下结果于 2026-10-30 测得：

| 项目 | 条件 |
| --- | --- |
| imx 版本 | 0.2.0 |
| 架构 | x86_64 |
| 系统 | WSL2 Linux `6.18.33.2-microsoft-standard-WSL2` |
| 编译模式 | 默认 `safe` 模式，终端库使用 `fast` 模式 |
| 终端 | 80×24，Bash |

PSS 表示按比例分摊共享页面后的物理内存。后台、连接客户端、shell 和会话程序分别统计。

## 空闲会话

会话完成初始化后分离，历史仅包含初始化输出。

| 空闲会话数量 | 后台 PSS | 后台进程数量 | 后台线程数量 |
| --- | --- | --- | --- |
| 1 | 1.47 MiB | 1 | 1 |
| 10 | 2.02 MiB | 1 | 1 |
| 100 | 6.38 MiB | 1 | 1 |

每种场景的 5 秒空闲采样中，后台 CPU 时间、主动进程切换和被动进程切换增量均为零。这些数值表示该次采样结果，具体资源占用随系统、终端尺寸和会话内容变化。

连接中的客户端 PSS 约为 0.75 MiB，静态可执行文件大小约为 1.77 MiB。

## 持续输出

无人连接时使用 `seq` 输出 500,000 行：

| 项目 | 结果 |
| --- | --- |
| PTY 接收数据 | 约 3.89 MB |
| 生成并处理输出耗时 | 约 0.57 秒 |
| 后台 CPU 时间 | 约 0.25 秒 |
| 输出后的后台 PSS | 约 3.84 MiB |
| 保留的纯文本 | 2,902 行，包含当前屏幕 |

## 在本机复测

需要 Zig 0.17.0、uv、Python 3.12 或更新版本和 Bash。在仓库根目录执行：

```bash
zig build
mkdir -p work/runtime
TMPDIR="$PWD/work/runtime" uv run --frozen --project tests python tests/benchmark.py
```

测量脚本启动真实 PTY、Bash 和会话程序，分别统计后台、客户端和 shell 的资源占用。完整结果写入 `work/benchmark.json`，包含 CPU 时间、进程切换、内存和输出处理数据。
