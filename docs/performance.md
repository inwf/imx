# 性能说明

## 资源管理

每个会话使用独立的后台进程，内部运行一个事件循环线程。后台进程使用 `epoll` 和 `signalfd` 等待事件；没有输入、输出或控制请求时，阻塞等待内核通知。每个后台单独拥有所属会话的 PTY、程序、屏幕、历史和客户端队列。

创建会话及最后一个客户端分离时，调用终端库的页面容量压缩和释放接口，释放闲置的预留页面。持续输出期间使用页面池；光标仍然持有样式或超链接引用的页面保持引用表。

交互客户端使用一个分屏管理进程，为每个窗格保存独立的 PTY、终端状态和输入队列，并通过 `poll`、`signalfd` 等待事件。连接会话的窗格运行连接进程，新建窗格运行普通 shell。Ghostty 维护窗格的屏幕和历史，libvaxis 绘制发生变化的内容；等待终端输出发送完成后才继续绘制。窗格中的普通 shell 及其作业随窗格关闭而终止，会话程序由独立后台管理。

| 项目 | 限制或处理方式 |
| --- | --- |
| 历史 | 10,000 行目标及 2 MiB 的历史容量，按完整终端页面修剪 |
| 当前屏幕和终端状态 | 另行占用内存 |
| 会话实时输入、输出队列与窗格输入队列 | 每个队列最多 256 KiB |
| 分屏绘制队列 | 最多 16 MiB，用于容纳完整屏幕更新 |
| 终端快照 | 按 16 KiB 分批发送，后续实时输出保持顺序 |
| 慢速连接 | 超过输出容量限制时断开，会话继续运行 |
| 终端尺寸 | 最多 512 列、256 行 |

## 测量环境

以下结果于 2026-11-01 测得：

| 项目 | 条件 |
| --- | --- |
| 测量对象 | 支持独立会话后台及分屏的开发版本 |
| 架构 | x86_64 |
| 系统 | WSL2 Linux `6.18.33.2-microsoft-standard-WSL2` |
| 编译模式 | 默认 `safe` 模式，终端库使用 `fast` 模式 |
| 终端 | 80×24，Bash |

PSS 表示按比例分摊共享页面后的物理内存。后台、客户端、shell 和会话程序分别统计；客户端数据合计分屏管理进程和各个窗格的连接进程。

## 空闲会话

会话完成初始化后分离，历史仅包含初始化输出。

| 空闲会话数量 | 后台 PSS | 后台进程数量 | 后台线程数量 |
| --- | --- | --- | --- |
| 1 | 2.26 MiB | 1 | 1 |
| 10 | 4.86 MiB | 10 | 10 |
| 100 | 30.96 MiB | 100 | 100 |

内存和线程数量均为全部会话后台的合计。相同可执行文件的只读页面由内核共享，PSS 按实际共享比例分摊；每个进程的可写数据、终端状态和队列独立分配。

每种场景的 5 秒空闲采样中，后台 CPU 时间、主动进程切换和被动进程切换增量均为零。这些数值表示该次采样结果，具体资源占用随系统、终端尺寸和会话内容变化。

单个窗格连接会话时，管理进程与连接进程合计 PSS 约为 2.19 MiB。静态可执行文件大小约为 2.67 MiB。

## 分屏客户端

在 100×30 终端中创建两个左右排列的窗格，分别连接两个会话：

| 项目 | 结果 |
| --- | --- |
| 客户端进程数量 | 3，包含一个管理进程和两个连接进程 |
| 客户端线程数量 | 3 |
| 客户端 PSS 合计 | 4.07 MiB |
| 5 秒空闲采样 CPU 时间增量 | 0 秒 |

会话后台、普通窗格 shell、会话 shell 和会话程序另行占用资源。增加窗格会增加 PTY、终端状态、绘制内容和对应的程序进程；实际内存随窗格尺寸、屏幕及历史内容变化。

## 持续输出

无人连接时使用 `seq` 输出 500,000 行：

| 项目 | 结果 |
| --- | --- |
| PTY 接收数据 | 约 3.89 MB |
| 生成并处理输出耗时 | 约 0.55 秒 |
| 后台 CPU 时间 | 约 0.24 秒 |
| 输出后的后台 PSS | 约 4.63 MiB |

## 会话响应与故障隔离

一个会话持续执行 `yes CONTINUOUS_OUTPUT`，另一个会话连续执行 100 次 shell 命令，测量从发送命令到收到结果和提示符的时间：

| 项目 | 结果 |
| --- | --- |
| 健康会话响应中位数 | 1.14 毫秒 |
| 健康会话最长响应时间 | 2.40 毫秒 |
| 存在暂停后台时的列表查询 | 1,003 毫秒 |
| 存在暂停后台时的名称补全 | 252 毫秒 |

列表并发查询后台，共享一秒期限；名称补全共享 250 毫秒期限。结果包含命令启动和输出时间。暂停后台的列表状态为 `unresponsive`，健康后台继续提供正常信息。隔离测试还验证多个后台同时暂停时的期限、其他会话的创建和交互、后台被强制终止后的程序及历史保留，以及暂停后台的卸载。

## 在本机复测

需要 Zig 0.17.0、uv、Python 3.12 或更新版本和 Bash。在仓库根目录执行：

```bash
zig build
mkdir -p work/runtime
TMPDIR="$PWD/work/runtime" uv run --frozen --project tests python tests/benchmark.py
```

测量脚本启动真实 PTY、Bash 和会话程序，分别统计后台、客户端和 shell 的资源占用。完整结果写入 `work/benchmark.json`，包含 CPU 时间、进程切换、内存和输出处理数据。
